## Change Details

### Language Configuration Hot-Reload Details

**Change** (61cd68d): Fix language configuration hot-reload issue to support immediate language changes

**Problem Description**:

In v1.0.3 and earlier versions, modifying the `shell-formatter.language` configuration in `settings.json` did not immediately update the extension UI language. The window had to be reloaded for changes to take effect.

**Solution**:

Added language change detection logic to the configuration change listener. When a language configuration change is detected, the i18n system is automatically reinitialized.

**Code Changes**:

```typescript
// src/entrypoints/listeners/config-change-listener.ts
import { initializeI18n } from "../../i18n";

// Step 2: If language configuration changed, reinitialize i18n system
if (languageChanged) {
    const newLanguage = SettingInfo.getLanguage();
    logger.info(`Language configuration changed to: ${newLanguage}`);
    initializeI18n(newLanguage);
    logger.info("i18n system reinitialized with new language.");
}
```

**User Experience Improvements**:

- ✅ Language configuration changes take effect immediately without reloading the window
- ✅ Automatically reinitialize i18n system to ensure all UI elements use the new language
- ✅ Add logging for debugging and tracking language changes

### Code Import Path Mapping Details

**Change** (c98544b): Configure package.json imports to support #/ path mapping

**Problem Description**:

In v1.0.3, code import paths were not unified, with some using relative paths and others using absolute paths, reducing code maintainability.

**Solution**:

Added `.js` extension to the `imports` field in `package.json` to enable Node.js to correctly resolve `#/` path mapping, unifying src directory code imports using the `#/` prefix.

**Configuration Changes**:

```json
{
  "imports": {
    "#/*": "./src/*.js",
    "#/utils/*": "./src/utils/*.js",
    "#/config/*": "./src/config/*.js",
    "#/domain/*": "./src/domain/*.js",
    "#/application/*": "./src/application/*.js",
    "#/entrypoints/*": "./src/entrypoints/*.js",
    "#/infrastructure/*": "./src/infrastructure/*.js",
    "#/i18n/*": "./src/i18n/*.js",
    "#/shared/*": "./src/shared/*.js"
  }
}
```

**Code Examples**:

```typescript
// Use #/ prefix for unified imports
import { logger } from "#/utils/log";
import { SettingInfo } from "#/config";
import { initializeI18n } from "#/i18n";
```

**Benefits**:

- ✅ Unify code import paths, improving readability
- ✅ Reduce usage of relative paths, lowering maintenance costs
- ✅ Support modern Node.js subpath imports

## Upgrade Guide

This version is a backward-compatible upgrade, no configuration changes required.

**Recommended Actions**:

- Update extension to the latest version
- Configure `shell-formatter.language` parameter to enable automatic

  after configuration modification
