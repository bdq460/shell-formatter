### 语言配置热更新详情

**变更** (61cd68d): 修复语言配置热更新问题，支持语言更改立即生效

**问题描述**:

在 v1.0.3 及更早版本中，修改 `settings.json` 中的 `shell-formatter.language` 配置后，扩展界面语言不会立即更新，需要重新加载窗口才能生效。

**解决方案**:

在配置变更监听器中添加语言变更检测逻辑，当检测到语言配置变更时，自动重新初始化 i18n 系统。

**代码变更**:

```typescript
// src/entrypoints/listeners/config-change-listener.ts
import { initializeI18n } from "../../i18n";

// 步骤 2: 如果语言配置变化，重新初始化 i18n 系统
if (languageChanged) {
    const newLanguage = SettingInfo.getLanguage();
    logger.info(`Language configuration changed to: ${newLanguage}`);
    initializeI18n(newLanguage);
    logger.info("i18n system reinitialized with new language.");
}
```

**用户体验改进**:

- ✅ 语言配置更改立即生效，无需重新加载窗口
- ✅ 自动重新初始化 i18n 系统，确保所有界面元素使用新语言
- ✅ 添加日志记录，便于调试和追踪语言变更

### 代码导入路径映射详情

**变更** (c98544b): 配置 package.json imports 支持 #/ 路径映射

**问题描述**:

在 v1.0.3 中，代码导入路径不够统一，部分使用相对路径，部分使用绝对路径，降低了代码的可维护性。

**解决方案**:

在 `package.json` 的 `imports` 字段中添加 `.js` 扩展名，使 Node.js 能正确解析 `#/` 路径映射，
统一 src 目录下的代码使用 `#/` 前缀导入。

**配置变更**:

```json
{
  "imports": {
    "#/*": "./src/*.js",
    "#/utils/*": "./src/utils/*.js",
    "#/config/*": "./src/config/*.js",
    "#/domain/*": "./src/domain/*.js",
    "#/application/*": "./src/application/*.js",
    "#/entrypoints/*": "./src/entrypoints/*.js",
    "#/infrastructure/*": "./src/infrastructure/*.js",
    "#/i18n/*": "./src/i18n/*.js",
    "#/shared/*": "./src/shared/*.js"
  }
}
```

**代码示例**:

```typescript
// 使用 #/ 前缀统一导入
import { logger } from "#/utils/log";
import { SettingInfo } from "#/config";
import { initializeI18n } from "#/i18n";
```

**优势**:

- ✅ 统一代码导入路径，提高可读性
- ✅ 减少相对路径的使用，降低维护成本
- ✅ 支持现代 Node.js 的子路径导入（Subpath Imports）
