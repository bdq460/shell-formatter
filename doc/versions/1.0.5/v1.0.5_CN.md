## 变更详情

### Git 虚拟文档诊断路径映射修复详情

**变更** (4c984c6): 新增 URI 规范化机制，解决 VSCode Git 扩展虚拟文档的诊断显示异常问题

**问题描述**:

VSCode Git 扩展会为同一 shell 文件创建虚拟文档（scheme 为 `git`，文件名带 `.git` 后缀），例如：

| 类型 | URI 示例 |
|------|----------|
| 真实文件 | `file:///path/to/service.sh` |
| Git 虚拟文档 | `git:/path/to/service.sh.git` |

这导致：

- 问题面板显示错误的文件名 `service.sh.git`
- 诊断行号与实际打开的文件内容不对应
- 用户点击问题无法正确跳转到代码位置

**解决方案**:

在 `src/shared/file-checker.ts` 中新增 `normalizeToFileUri()` 函数，将 `git:` scheme 的虚拟文档 URI 映射回真实的 `file:` URI：

```typescript
export function normalizeToFileUri(uri: vscode.Uri): vscode.Uri {
    if (uri.scheme === "file") return uri;

    const fileName = uri.fsPath.split("/").pop() || "";
    const gitSuffix = /\.git$/;
    if (uri.scheme === "git" && gitSuffix.test(fileName)) {
        const realPath = uri.fsPath.replace(gitSuffix, "");
        return vscode.Uri.file(realPath);
    }
    return uri;
}
```

**影响范围**:

修改了以下 5 处 `diagnosticCollection.set()` 调用点，确保所有诊断信息均使用规范化的文件 URI：

| 文件 | 说明 |
|------|------|
| `src/shared/file-checker.ts` | 新增 `normalizeToFileUri()` 函数 |
| `src/entrypoints/listeners/open-listener.ts` | 打开文档时使用规范 URI |
| `src/entrypoints/listeners/save-listener.ts` | 保存文档时使用规范 URI |
| `src/entrypoints/listeners/change-listener.ts` | 文档变更时使用规范 URI |
| `src/entrypoints/commands/fix-command.ts` | 修复命令中诊断更新使用规范 URI |
