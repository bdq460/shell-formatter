## Change Details

### ES Modules Migration Attempt Details

**Change** (028a092): ~~Migrate project from CommonJS to ES Modules~~

**Attempted Changes**:

- Update `package.json` to add `"type": "module"`
- Refactor all `require()` to `import` statements
- Update `tsconfig.json` module configuration
- Adjust testing framework to support ESM

**Failure Reasons**:

- VSCode extension uses Node.js 16.15.0 which doesn't support `#/` path aliases
- `package.json` `imports` field doesn't work in VSCode extension environment
- Runtime error: `Invalid module "#/application"`

**Final Solution**:

- Reverted to CommonJS module system
- Removed path aliases, switched to relative paths
- Kept `tsconfig.json` with `module: "commonjs"` configuration

### Hexagonal Architecture Refactoring Details

**Change** (0e357db, a999d5b, 6de6701): Refactor architecture with clear layer boundaries

**Architecture Layers**:

```text
src/
├── entrypoints/     # Entry Layer: VSCode API interaction
├── application/     # Application Layer: Use case implementation
├── domain/          # Domain Layer: Core business logic
├── infrastructure/  # Infrastructure Layer: External adapters
└── utils/           # Utils Layer: Common utilities
```

**Design Principles**:

- Dependency direction: Outer → Inner
- Domain layer is completely independent
- Decouple layers through dependency injection

## Upgrade Guide

### Upgrading from v1.0.1

2. Reinstall extension
