## 变更详情

### ES Modules 迁移尝试详情

**变更** (028a092): ~~将项目从 CommonJS 全面迁移到 ES Modules~~

**尝试过程**:

- 更新 `package.json` 添加 `"type": "module"`
- 重构所有 `require()` 为 `import` 语句
- 更新 `tsconfig.json` 模块配置
- 调整测试框架以支持 ESM

**失败原因**:

- VSCode 扩展运行时的 Node.js 版本（16.15.0）不支持 `#/` 路径别名通配符
- `package.json` 的 `imports` 字段配置在 VSCode 扩展环境中无法正常工作
- 运行时出现 `Invalid module "#/application"` 错误

**最终方案**:

- 回退到 CommonJS 模块系统
- 移除路径别名，改用相对路径
- 保持 `tsconfig.json` 的 `module: "commonjs"` 配置

### 六边形架构重构详情

**变更** (0e357db, a999d5b, 6de6701): 重构项目架构，明确分层边界

**架构分层**:

```text
src/
├── entrypoints/     # 接入层：VSCode API 交互
├── application/     # 应用层：用例实现
├── domain/          # 领域层：核心业务逻辑
├── infrastructure/  # 基础设施层：外部适配器
└── utils/           # 工具层：通用工具函数
```

**设计原则**:

- 依赖方向：外层 → 内层
- 领域层完全独立，不依赖其他层
- 通过依赖注入解耦各层

## 升级指南

### 从 v1.0.1 升级

1. 更新 VSCode 至 1.80.0 或更高版本
2. 重新安装扩展：`code --install-extension shell-formatter-1.0.2.vsix`
3. 检查自定义配置是否需要调整

### 兼容性说明

- **VSCode 版本**: 最低要求 1.80.0
- **Node.js 版本**: 14.0.0+
- **操作系统**: Windows, macOS, Linux

## 已知问题

- 路径别名 `#/` 在 VSCode 扩展环境中不被支持，已改用相对路径
- 首次加载时可能需要稍长时间初始化 i18n
